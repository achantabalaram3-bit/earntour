# RCA — Deploy build failure (run 1190d1f5-860e-4c07-a8fd-9610914459b8)

## Summary
The redeploy failed at the **build_image** step during the frontend `yarn build`
(craco/ESLint compile). It is a **source-code syntax error**, not a manifest,
infra, or configuration problem. No manifest change or retry can fix it — the
frontend source must be corrected and the deploy re-triggered.

## Exact error (Cloud Build, step #2 "docker-build", frontend-build stage)
```
Creating an optimized production build...
Failed to compile.

[eslint]
src/world/components/FreeWorldNumberSequenceV3.jsx
Syntax error: Unexpected token (2498:0) (2498:undefined)
error Command failed with exit code 1.
```

## Root cause
`frontend/src/world/components/FreeWorldNumberSequenceV3.jsx` is corrupted by a
bad edit/merge. A duplicated copy of the **top-of-file block** — the module
`import { ... } from 'react'` / `lucide-react` / `../../lib/api` / `react-dom` /
`sonner` / `react-router-dom` / css imports, followed by helper functions
(`shuffle`, ... , and a **truncated** `getErrorMessage(error, fallback) { const detail =`)
— was pasted into the MIDDLE of the component's error-state JSX `return(...)`.

It sits between:
- line 2491: `        </h2>`  (inside `return ( <div className="fwv3-overlay"> <section ...> ... <h2>Attempt unavailable</h2>`)
- line 2588: `        <p>`   (the error message paragraph that legitimately continues the same JSX)

`import` statements are only legal at module top level, so the parser hits the
duplicated `import {` (its `} from 'react';` lands on line 2498) inside JSX and
throws "Unexpected token (2498:0)". Confirmed structurally:
- `} from 'react';` appeared TWICE — line 7 (legit) and line 2498 (duplicated junk).
- `function shuffle` appeared TWICE — line 34 (legit) and line 2525 (duplicated junk).
- `export default function FreeWorldNumberSequenceV3(` appears ONCE (line 116), and
  the file tail (the `<p>{error || 'Unable to continue this attempt.'}</p>`,
  `RETURN TO WORLD` button, closing `</section></div>);`) is the correct completion
  of the error return — i.e. the junk is an inserted block, not a doubled file.

## Fix (apply in the source repo)
In `frontend/src/world/components/FreeWorldNumberSequenceV3.jsx`, **delete the
erroneously-duplicated block, lines 2492–2587 inclusive**, so that `</h2>`
(line 2491) is immediately followed by `<p>` (currently line 2588) at the same
8-space indentation. Result around the join:

```jsx
        <h2>
          Attempt unavailable
        </h2>
        <p>
          {
            error ||
            'Unable to continue this attempt.'
          }
        </p>

        <button
          type="button"
          className="fwv3-button fwv3-button-primary fwv3-full"
          onClick={onClose}
        >
          RETURN TO WORLD
        </button>
```

The deleted block is pure duplication (it begins with the identical top-of-file
imports and re-declares `shuffle`/other helpers already present in lines 1–115),
so removing it loses no unique logic.

Line numbers are from the failing run's source; if they've since shifted, the
anchor is: remove the stray `import {...}`/helper-function block that appears
BETWEEN `<h2>Attempt unavailable</h2>` and the `<p>{error || 'Unable to continue
this attempt.'}</p>` inside the component's final (error-state) `return`.
